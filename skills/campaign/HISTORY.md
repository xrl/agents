# Campaign history: Things that bite

The complete former "Things that bite" section of [SKILL.md](SKILL.md), all 66 bullets as they stood at xrl/agents `cc070358504191cc739c6aaecf124e91da8682aa`, with their receipts. Incident evidence only: not standing rules, and no entry point tells an agent to read it first. The 15 bullets that change what an agent does next are kept in SKILL.md (and also appear here, numbered, so nothing is lost).

1. The classifier refuses destructive git (`reset --hard`, deleting a remote branch). Cut a new worktree and branch instead and leave the old ones for the owner.
2. A smoke read must be small. A broker-limited host refuses a large page outright (`broker HTTP response exceeded its limit`), which reads as a provider failure: `crates.io/api/v1/crates/serde` failed where `crates/<name>/<version>` passed. Name a small, stable read per provider in the smoke packet.
3. A rollout smoke covers every capability whose provider version or credential changed, not one read per provider. Cruciferous Loop 8 smoked gh with `gh auth status` while the new `pr checks` grant was broken (fixed in rpi-homelab #252). After the Skylight credential migration the smoke ran only `skylight frames`, and every `skylight tasks` read returned 422 (IDEA-0071).
4. The driver runs with `-nc`: no global context files. Put the machine's Rust rules in its read list (`~/code/xrl/agents/RUST_AGENT_RULES.md`).
5. A pi turn is found by its pid file, never by `pgrep`.
6. No heartbeat means a hung turn stalls the run until someone looks; none hung in sub-campaign 4.
7. A subagent's completion notice can arrive before its hand-back message for the same turn; check the PR, not the notice.
8. `gh run view`/`gh pr checks` from a non-repo cwd fail silently: always pass `-R <owner/repo>`.
9. Every correction is a new commit on top, before or after a push and within a PR; no prompt says "amend" (LAWS §56).
10. A driver that runs under DRIVER.md's third-FIX stop refuses a fix unless the prompt quotes the coordinator decision that authorizes it.
11. A ruling sent to a lane that cannot ask back (Codex through a relay, a cloud session) is checked against the brief, row by row, before it is sent, and it goes to every arm building the same unit. 2026-10-10, T1c bake-off: a relayed scope ruling told Codex that pre-admission refusals record `failed` where the brief said the refusal outcome; both judges' decisive findings against the Codex build were that ruling's.
12. Grepping task output files can pull whole subagent transcripts into the coordinator's context; read only the named output of a Bash task.
13. A Bash background task dies at 2 h. A pi supervisor turn that runs several steps outlives that, and its driver dies with it (the RG supervisor died mid-RG-b, 2026-10-02). Launch one supervisor turn per step.
14. An API 529 (Overloaded) can end a Claude unit agent mid-step. Its pi supervisor turn runs on in its own background Bash task and finishes the step. Resume the agent with SendMessage, naming the supervisor's exit receipt and its `supervisor-state.md`. Never relaunch the step. If the resume hits a 529 too, wait ten minutes and send it again (sub-campaign 10 unit 6: two 529s, SHIP completed untouched).
15. Launch a pi turn with `run_in_background`. A foreground `&` is killed as soon as the call returns.
16. Deleting a live unit's `target/` forces a cold rebuild. Overlapped with another build, it dipped free disk from 69 to 13 GiB for a minute. Check disk when a build launches, never in the middle of one.
17. When a pilot needs a core fix while a driver owns the core worktree, commit the fix on a side branch cut from the pushed head. The pilot pins to it, and the core step cherry-picks it. That keeps one writer per worktree.
18. Start the PR's Fable read at the pushed head beside the unit's last CI wait, never after it: it needs the local head, not CI. A CI fix commit gets a scoped re-read of its delta, so the merged head is still the reviewed one.
19. Authority is stated once, in EPOCH.md §Execution contract with its `LIMITS.toml [authority]` table, and answered at the gate from the authority ledger; every prompt points to it, quoting it by reference, never restating it. Approving a sub-campaign authorized its releases, but the classifier refused the coordinator's next action as "Merge Without Review" right after it merged a reviewed, green core PR, and work stopped until the owner said "merges authorized" (sub-campaign 11, #478). Under the runner the tick merges in shell, outside the classifier.
20. The classifier refuses `gh pr merge` into a shared workflow repo whose `@main` other repos call. Ask the owner for that merge up front.
21. Start a step when its own dependency lands, not when the whole unit does. 2026-10-03: curl's typed-SDK migration needed only S1b on main but waited for S2, so the testkit defect it found surfaced hours late.
22. Before a push, the driver runs CI's own steps for what it touched: every generated artifact CI byte-compares, every docs check its change triggers, `cargo doc` with `-D warnings`, `cargo deny`. The repo's own list lives in its agent guide. 2026-10-03: four CI reds (a rustdoc link, an advisory, generated bytes, an undocumented event) each cost a fix turn plus a CI cycle.
23. A pi turn that dies on `fetch failed` twice is a network problem, not a model one. Hand the half-done easy fix to one Claude agent working from the uncommitted diff rather than retrying a third time.
24. `gh pr merge --rebase` rewrites SHAs. A pilot that must pin to the merged commit waits for the merge, then pins to `mergeCommit.oid`.
25. Every background probe, watch or poll loop runs under `timeout <s>`, never `while true`. A loop left by the v0.32 rollout session hit the WhatsApp webhook every 5 s for 23 hours; a day later its 15,000 refusals looked like a production fault and cost a diagnosis.
26. `cm close` needs every step at `done` or `blocked:<reason>`, and `done` comes only after `released` (a tag) and `deployed` (a digest). Take the tag from `git tag --contains <merge sha>` in the step's repo; `cm` accepts any tag that resolves, so the closer checks that the tag contains the merge. Take the digest from what the RPi runs: the pod's image ID, or a provider-set pin matched against its registry tag. Pass `--repo` once the worktree is reaped. A step that was released but is not live, docs only, a study, or superseded by a split closes as `blocked:<one-word-reason>` (Cruciferous close, 2026-10-17).
27. A smoke leg's verdict never comes from scraping the console TUI. Bordered echoes, repaint and sidebar text, and a provider printing its own `[exit code: 0]` each fooled a matcher: three verifier rounds in sub-campaign 11 (CONSOLE-DEV, R11-14..16). A leg passes on the broker's record of the call (Succeeded in the leg's window) plus a result line the supervisor quotes from the saved screen. The script only captures.
28. A ruling that changes what a tool or script does names the step that edits it. R11-16 made the smoke script capture-only, but no step owned the edit, so ROLLOUT stopped at the smoke (sub-campaign 11, ROLLOUT ruling 1).
29. dekopon core PR CI: p90 9 min; deadline 12 (`core_pr_ci_deadline_min = 12`). An 8-minute watch hands back every core PR (sub-campaign 11, #478/#479/#480; p90 from the 2026-10-16 CI study).
30. Smoke-test probes come from each provider's own `help` or capability list, not from the CLI tool it imitates. The v0.33 gh probe used `--limit` and `--state merged`, which the gh provider does not take.
31. No spans is not a broken exporter. Spans exist only when there is traffic: before calling a telemetry gap a fault, send one known request and look for its span (2026-10-04: a five-hour gap was a quiet evening).
32. Proportion the ceremony. Config chores and small single-repo changes take a sol recon, then a sol supervisor + driver + one sol verifier per commit: no Fable plan check, no dry run. Four chore lanes landed that way on 2026-10-04 (curl grant, console assets, two homelab cleanups); the one fix round the verifier forced closed three real holes.
33. pi's built-in `process` tool survives `-ne`, and a supervisor may prefer it, citing a harness rule over the packet. A driver started that way dies when the supervisor's turn ends. Every packet, and every hand-written fix, re-check or resume prompt, forbids the `process` tool, `bg_wait` and any managed background process by name. A driver on a fix prompt without that line ran its gates under `process`, ended the turn with "I'll push only if they pass", and lost the gate run and its push (2026-10-12, provider-gh #20 fix round 1). If a supervisor also refuses `nohup`, the foreground launch in `templates/SUPERVISOR.example.md` is the answer: it holds the turn open, which is the in-turn wait anyway (sub-campaign 8, PYTHON rulings 1-2).
34. A supervisor that looks for other supervisors finds its own pi process and stops. It happened three times on 2026-10-04 (R1, ROLLOUT, CLEANUP), the third after the packet defined a duplicate as "a live pid file with no receipt, never your own process". Defining it does not work; forbidding the check does. Every packet says: do not check for other supervisors, the coordinator launches exactly one per lane; check only the lane's DRIVER pid files. The coordinator's launch or resume prompt names the session ("You are <session>, the only supervisor for this lane").
35. A supervisor can launch its driver before it has created the driver's worktree; `pi-turn.sh` then exits 1 at `cd`. Packets say "create the worktree, then launch".
36. Heavy-build counting in the launch wrapper alone misses builds that start later in a long turn: the python driver overlapped six fleet builds (sub-campaign 8). The driver counts live builds before each heavy build, not only at launch.
37. A version bump changes every checked example `.wasm`: the crates' exact pins reach the guest build. The byte proof is the local pinned rebuild against CI's pinned rebuild, never against the old bytes; the WIT imports and exports must match the previous release. Sub-campaign 9's SHIP stopped on a rule that compared against the old bytes.
38. A homelab commit that touches both `apps/dekopon.yaml` and `manifests/dekopon/` is two Argo applies: app-of-apps owns the first, the child app the second. If the child syncs first, it prunes what the old pod template still mounts, and the pod wedges. Chain the merge with the app-of-apps hard refresh and sync. Touch the child only once its `targetRevision` shows the new chart. Sub-campaign 9's rename rolled out that way with a 54 s outage.
39. The PR image check builds from the latest published release, so a binary rename fails it until the renamed release exists. Gate PR mode on the release version, and delete the gate in the first PR after the tag (sub-campaign 9, R9-15 and #464).
40. Start a dependent lane from a `timeout`-bounded until-loop on the artifact it needs, not from the previous lane's report. In sub-campaign 9, CONSOLE started on a crates-ready watcher in the middle of SHIP and finished first.
41. Before reaping a worktree at a landing, grep the later steps' packets for its path. A packet that names it as a read-only cwd stops its supervisor at launch (sub-campaign 2: SMOKE stopped because it named the V worktree just reaped after the merge). Repoint the packet to a detached worktree at the release tag.
42. Console smoke runs `dekopon-console --agent <agent> --no-color` (the RPi's is `ville-github`) and the provider's own command word (vm's is `ssh`). A bare `dekopon-console` attests as a subject with no attestor and is refused `no attestor authority for this subject`: an invocation error, not an owner credential refusal (sub-campaign 2 SMOKE ruling 2). A provider whose only ReadOnly call needs an existing async job (vm `ssh --job`) is proven at help level plus the direct API path; journal the gap.
43. Every Opus code-only fix prompt says: a fix to unreleased work carries no `Changelog:` line; run `cargo fmt --all` before committing; the driver may change Opus's lines only by `cargo fmt --all` output, taken verbatim (it may remove tokens such as redundant braces). Sub-campaign 2 V2R: `Fixed` lines and a "no token changes" ruling cost two supervisor turns.
44. Dashboard SQL never selects a field that is emitted only on a rare path: OpenObserve fails the whole panel with HTTP 400 `unknown field` until the first such record lands. The ASSEMBLE dashboard audit checks each selected column has been emitted by the smoke's ordinary traffic (sub-campaign 2: GUEST_BY_SESSION and `vm_runner_guest_timed_out`, homelab #172).
45. Schedule a post-rollout check at the earliest point its witnesses exist, not at a fixed "+24 h". That point is the latest predicted event it must see (an idle reap at 30 min) plus one ordinary hour clear of rollout and smoke traffic. Run it from the closing session, not a fresh one the next day. A volume bound measured in an hour with no unit traffic bounds only the baseline, so the report also gives the per-session record count from the smoke. Sub-campaign 2: the owner waived a 19-hour wait; the check ran about 5 h after the rollout ($0.20 of pi), saw the idle end, and got 1,440 records/day from `telemetry.health` alone.
46. Prove a limit by forcing it, not by waiting for zero events. A soak at a generous cap only shows that traffic was low. Squeeze the cap on a test route, drive a few messages until it refuses, wait out the window, then restore it. 2026-10-13, Bounded Bounces G1: a seven-day zero-refusal `metering.yaml` read (real peak ~1% of 20M) gave way to ville-github at 20k/5m (a mid-turn wait refusal, recovery after one window) and 9k/5m (never fits). That took three homelab PRs, ~17k model tokens and 25 minutes, and it found a Slack rendering bug on the way.
47. A close condition that waits for a natural event ("one Scientist stop carries its cause") names, at planning, the forced witness that stands in if the event never happens. Otherwise the close waits on luck. 2026-10-13: no Scientist stop came in the 18 h after F1 went live, so the witness was recorded as a gap. A cancel and four over-budget refusals on ville-github proved the same typed-cause path.
48. Check a browser driver's story against telemetry before journaling it. 2026-10-13: the Slack driver reported A2 as "refused up front, no tools ran", but the meter rows showed one call charged before the mid-turn refusal.
49. A step prompt names only config keys it found in a sibling file or the binary's schema, with the locator. Sub-campaign 10's packet writer turned the brief's "64 KiB response" into an invented `maxOutputBytes`; the strict broker check refused it and cost a supervisor turn (ROLLOUT ruling 1, R10-9).
50. The shared `provider-workflows` release workflow is a provider's release contract: three assets (wasm, `.sha256`, CycloneDX SBOM), marked latest. Per-repo `RELEASE.md` files that say "exactly two assets, never latest" are stale (curl, jsonplaceholder); verify templates say so. Prove the attestation with `gh attestation verify <wasm> -R <repo> --signer-repo dekopon-agents/provider-workflows` and the OCI layer with `crane manifest`/`crane digest` (`oras` is not installed).
51. A gate counts only what its own lane created. A container or image another session left behind is recorded as pre-existing, never stopped, and never turns the gate red. A local pre-push step never runs a repo CI script or Compose file that starts Docker (a chart permission script, an OpenObserve smoke): the PR's CI runs it on GitHub's runner and is authoritative. Advanced-schlubbing: a pre-existing labelled container stopped the 0.39.0 rollout, and repo CI scripts that start Docker stopped the 0.40.0 release three times.
52. A PR branch catches up by rebasing onto `origin/main`, never by merging main into it. A rebase-only repo refuses a branch with a merge commit, and the fix is a linear rebase plus a range-diff read before merge. Every fixer prompt says "rebase, never merge main". Advanced-schlubbing: #499 and #500 both carried merge commits from main; #499 could not merge until its fixer rebased it.
53. A core release is two tags, core then chart, and the chart is cut from main. Every other core PR holds until the chart tag exists, then merges one at a time, each riding the next minor. A merge between the two tags puts unreleased code under the chart's tag.
54. Every brief, recon included, says: never read or print a credential file (`~/.config/dekopon/broker-credentials.yaml`, auth JSON, kubeconfigs); a step that needs one edits a scratch copy by script or skips the call. A read-only recon agent is not safe by being read-only: one printed both GitHub PATs into its transcript, and rotation is the owner's.
55. The harness may refuse a Claude subagent's report-file write ("Subagents should return findings as text, not write report files"); a chapter or packet it was asked to produce writes fine. Briefs for findings say "return your findings as text in your final message", and the coordinator saves it where it belongs. Files that are the work product (a packet, a brief, code) are fine.
56. Every brief except a chore lane's (see "Proportion the ceremony") gets one Sonnet cold read before its builder launches, all briefs of a wave in parallel. The coordinator rules each blocking finding into the brief as a C-numbered ruling, then launches. Advanced-schlubbing: blocking findings in 5 of 10 briefs (a missing template source, an SDK-pin contradiction, an unanswered paging rule, a probe that would refresh a credential, a hook ordering that selective syncs skip).
57. A builder past about 300k tokens never takes its own review's fix round: a fresh Opus agent fixes on the same branch from the review and the builder's NOTES.md, then a re-check scoped to the findings. Resuming the builder re-reads its whole context on every call. Advanced-schlubbing: three fix rounds went that way (U9a, U8a, U9b) and every scoped re-check came back MERGE.
58. One rerun for a known flake. When the same test fails a third time across PRs, stop rerunning: launch one agent to fix it, told to measure before and after under load and to stop before any production change. A flake can be a real race. Advanced-schlubbing: #495, the brokerd shutdown-deadline "timing flake", was `timeout_at` polling the drain before the deadline, so a drain finished after it counted as clean and exited 0.
59. A homelab change of one or a few files (a pin, a grant block, a route flag) goes to one Opus agent with merge and Argo sync authorized, not a pi packet. It is the only homelab writer until it reports. Advanced-schlubbing: four such changes (rpi-homelab #186, #188, #189, #194) each merged, synced and verified live inside one agent run; a pi packet for a three-line change costs more than the change.
60. While ExternalSecrets fail (a 1Password rate limit), the child app's chained sync applies ConfigMaps, then stops on the ExternalSecrets before it reaches the Deployment. Reloader restarts the pod on the new ConfigMap with the old pod template. Diff the OutOfSync set first and run one selective sync of the ConfigMaps, config Secret and Deployment together; leave the ExternalSecrets alone. A provider-only change (sync hook + ConfigMap) is safe under the failure; a Deployment change is not. Advanced-schlubbing P3: the chained sync crash-looped the gateway about 3 minutes ("could not read skill file").
61. A kache store over its cap with GC evicting nothing is a kache fault (rule 2), not disk pressure to reap around. Read `kache stats` and `kache doctor`, put the numbers in OWNER-QUEUE with a purge recommendation, and stop the lane at its disk gate. Never purge on the coordinator's own call. Advanced-schlubbing: 51.2 GiB against a 40 GiB cap (128%), last GC evicted 0, doctor clean; purged on the owner's word.
62. A red check (the witness failing without the fix) builds in a scratch tree with its own `CARGO_TARGET_DIR=$scratch/target`, deleted afterwards, never a symlink to or copy of a worktree's `target/`. Every prompt that asks for a red check names where it builds. 2026-10-16, Cruciferous 07 S3 ruling 5: the coordinator's resume asked for a scratch red check without saying where, the driver symlinked the worktree's `target/`, and the next exact-head gate ran the scratch-built test binary and failed (cargo#17312, RUST_AGENT_RULES rule 3). The supervisor stopped correctly; a `cargo clean -p` and rebuild recovered.
63. A ruling that dictates user-facing text (a refusal message, a log line, a doc sentence) is checked against the config schema and the docs before it is sent. 2026-10-16, Cruciferous 07 S3 ruling 3: the prescribed `GithubBindNotShared` message told operators to "use a distinct callback path", a knob GitHub transports do not have; the Fable delta read flagged it after landing.
64. When main moves under a lane, the re-check at the rebased head is mandatory, and every verify template names the other lanes that are writing the same crate. Parallel lanes on one crate are allowed; that re-check is what catches their seam. 2026-10-16, Cruciferous 09 S5b ruling 3: 07 S3 (#602) landed a GitHub listener holding a boot-time copy of the routes while 09 S5b made routes live-reloadable; neither lane's base could show it, and only the re-check after S5b's rebase found it (one Opus fix, about 40 minutes).
65. A study's cleanup keeps every hashed artifact a later decision packet joins on until that packet is accepted. 2026-10-16, Cruciferous 13 S5 ruling 1: S3's cleanup removed the built Python Wasm and the run-copy broker after its review, so S5 could not hash them again and its comparison closed interim.
66. Changelog trailer wording or category is never blocking in a Fable read; the reviewer notes it for the squash message, and the coordinator fixes it there. `CHANGELOG.md` is written only at release prep from `git log`, so a trailer is a breadcrumb, not a merge gate (owner, 2026-10-16). Every Fable prompt says so. Cruciferous #604 came back FIX BEFORE MERGE over one trailer word.
